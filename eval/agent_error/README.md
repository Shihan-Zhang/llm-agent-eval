## 接入 ToolMaze 时处理的问题(读源码发现)

1. **P0 与 P1–P4 的系统提示词不同**(`evaluation/agents/openai_agent.py`):P1–P4 多了"工具可能失败"的故障处理指引,
   默认设置下 P0 与 P2 的差异混杂了扰动和提示词两个因素。正式实验把提示词作为独立因素
   (无提示 / 故障提示 / 证据契约)与 P0–P4 交叉,P0 列即过度拒绝的对照。
2. **上下文**:官方 `max_tokens` 32000、最多 25 轮,工具结果原样拼进对话。本地改为 `max_tokens` 2048,
   并用固定 `num_ctx 8192` 的模型变体(OpenAI 兼容接口不能逐请求传 `num_ctx`,否则 Ollama 静默截断)。
3. **暂时性扰动按工具名计数**(`sandbox.py::_should_perturb`):同名工具第二次调用无论参数都放行,
   "恢复"可能是碰巧;分析时读轨迹确认模型是否识别了坏数据。
4. **判分看轨迹和最终回答**,工具基本无状态,部分依赖 LLM 裁判 → 裁判用不同家族(硅基流动上的 DeepSeek),人工抽查校准。
5. **判分按路径而不是按结果**(E0 发现):P0 要求轨迹包含标准路径的每个工具;用功能等价的"一步到位"工具
   (如 `book_flight_with_status_check` 代替 `build_flight_booking_request` + 预订)会被判失败,即使确认码已拿到。
   与论文对比用官方判分;失败回合另做人工审计,报告"路径不同但结果正确"的比例。
6. **判分是纯规则的**:`judge.py` 只保存了 LLM 客户端,公开代码里从未调用;判分确定、零成本。
   LLM 裁判(硅基流动 DeepSeek-V3.2)改为用于失败回合的"结果是否正确"审计,并用人工标注校准(Cohen's κ)。
7. **并发**:本地 Ollama 串行处理,并发设 1;耗时用服务端计时,不用客户端墙钟时间。
8. **无属性 object 参数被 API 压成空值**(E2 阶段 C 发现):111 个顶层参数、8 个数组元素的 schema 只写 `type: object`、
   没有 `properties`。硅基流动上 Qwen3.5-35B-A3B 把它们传成 `{}`,DeepSeek-V3.2 传成 `""`;本地 Ollama 正常。
   官方判分按路径、不看参数内容,所以测不出来。修法:`toolmaze_run` 第 7 条补丁加 `additionalProperties: true`
   (见下方「E2 管线问题」)。

## E2:复现 Outcome Monitors(arXiv 2608.19303)——冻结的规格

运行时检查工具结果,违反从 P0 轨迹挖出的"结果契约"时,在原结果外附一张回执(违反的规则、期望值、实际值、
可用的备用工具),不改动作空间。代码:`contracts.py`(挖掘与检查)、`e2_manifest.py`(回合清单)。

以下内容**在看到任何 E2 结果之前定下,之后不改**;`tests/test_contracts.py` 校验代码中的规格与这里的哈希一致。

**契约数据**:主分析用题目自带的标准 P0 轨迹(C1–C4 共 400 道题;论文附录 P 也是 400 个 nominal 工作流),
敏感性分析用 E1 本地 qwen3i-8k 的 C1 P0 轨迹(100 题)。只读 P0;不读任务描述、扰动字段、判分结果。
5 折按 `task_id` 划分(种子 20261108,400 道题各有独立模板,构建时断言模板不跨折);评测第 k 折的题只用注册表 C_k。

**样本数门槛**(论文算法 2 原文):echo ≥ 2 对且全部相等;positivity ≥ 3 个数值样本且全部 > 0;
domain ≥ 4 个字符串样本、规范化(去首尾空格、小写)后 ≤ 8 个不同值;affine ≥ 4 个样本、各 ≥ 3 个不同值,
拟合容差 1e-8,运行时 1e-5;order ≥ 2 个可解析样本且全部 f ≤ g。

**论文未公开、由我们定义的部分**:

| 项 | 取值 | 依据 |
|---|---|---|
| 分类词表(字段名最后一段命中即算) | action, availability, category, channel, class, condition, currency, department, direction, exchange, kind, level, method, mode, priority, rating, severity, state, status, strategy, tier, trend, type, unit | 盘点 P0 输出的字段名(只看名字、类型、取值个数,不看 P1–P4 与结果),取"状态/类别"语义的词,排除编号、名称、文本 |
| 三组日期对(f ≤ g) | check_in_date ≤ check_out_date;start_time ≤ end_time;meeting_start_time ≤ meeting_end_time | 按全部 400 道 P0 题里"字段名在同一输出中的共现次数"选出(215 / 32 / 16),语义为"开始 ≤ 结束";只用字段名,不涉及任何数值,所以不构成泄露。可解析 ISO 日期、日期时间、HH:MM,同种类才比较 |
| 工具最少样本 | 2(少于 2 个样本的工具不建契约) | 论文未写;1 个样本时"全部字段都必有"过于激进 |
| 类型约束最少样本 | 2;整数可通过"数值"类型 | 论文未写 |
| explicit_error 字段名 | error, error_message, errors, exception(非空且不在该工具的正常字段中) | 论文附录 N 的触发实例为 `error` |
| order 违反的代码名 | temporal_order_violated | 论文未给 |

### E2 ② / ③ 计划(2026-11-09,运行前)

**可用工作流**:ToolMaze 的 C3、C4 各 100 题,每题都有 P0/P3/P4 文件(`e2_manifest.tasks_with_modes`),
所以 C3/C4 × P3/P4 共 400 个(题, 模式)组合、200 道不同的题。论文和冻结清单都是"每题只带一种故障模式",
在这个约束下最多 200 对;冻结清单用了 80 道题,剩 C3、C4 各 60 道没用过。

**检验功效**(`python eval/agent_error/power_e2.py --psi 0.15 --n 80 150 200`):精确 McNemar,双侧 α = 0.05,功效 80%,
不一致配对占比 ψ = 0.15(① API 实测 11/80 = 0.1375,取整到 0.15)。MDE 是能以 80% 概率检出的最小配对差 δ。

| n | MDE(精确 McNemar) | MDE(Connor 1987 近似) | 按 ① 实测折算的 API 开销 |
|---|---|---|---|
| 80 | 12.2% | 12.0% | 约 4.4 小时、$2.6 |
| 150 | 9.1% | 8.8% | 约 8.2 小时、$4.9 |
| 200 | 8.0% | 7.6% | 约 11 小时、$6.5 |

开销按 ① 的每对 263.8 分钟 / 80、$2.60 / 80 线性折算;② 两组都带回执,实际可能略多。

- **②(完整回执 vs 去掉备用工具列表)**:两组都重新跑,不复用 ① 的完整回执组(同一配置重跑才能随机交错、
  消除运行时间差异)。若备用工具列表贡献了 ① 的全部增益,预期 δ ≈ 13.8%,n = 80 刚好高于 MDE 12.2%;
  若只贡献一半(约 7%),n = 200 也检不出(MDE 8.0%)。所以 n = 80 只能回答"是否几乎全部来自备用工具列表",
  回答不了"贡献了多少"。**选定方案 B(2026-11-09):② 跑 200 对**(冻结清单 80 + 补充清单 120,见上方冻结规格),
  MDE 8.0%;③ 保持 80 对。② 的汇总另报两项:(a) 去掉 5 道与试跑重叠的任务后的敏感性分析;
  (b) 完整回执组在原 80 对上与 ① 的完整回执组逐对比较(一致率、Cohen κ),衡量温度 0 下重跑的稳定性。
- **③(P0:基线 vs 完整回执)**:同一批 80 道题的 P0。预测是"变化在 ±5pp 以内",而 n = 80 的 MDE 约 12%,
  所以 ③ 只能检出较大的伤害;"未检出差异"不等于"差异在 ±5pp 以内",报告里同时给 δ 的 Newcombe 区间。

### E2 管线问题:无属性 object 参数被压成空值(2026-11-09)

**现象**(`summarize_e2.py` 汇总里「运行完整性」一节逐组统计;判分调查见 `judge/survey.py` 第 6 节):

### E2 阶段 C:按结果判分——规则层(2026-11-09,不调用模型)

**为什么不用 ToolMaze 判分、也不只看最终回答**:ToolMaze 按路径判分,会漏掉结果错误。例如 C3_task_039 P3 换到另一条有效路径后
